# M1 tenancy and provisioning implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline, one owner of both Tenancy EF migration streams. The repository owner reviews architectural/security changes and merges.

**Goal:** Implement roadmap M1: one closed-by-default Orchard host, fixed platform database, four independent customer shells, protected resumable provisioning and evidence-backed readiness.

**Architecture:** Retain the M0 modular monolith and selective Orchard 3.0.1 packages. Platform registry owns immutable tenant identity, subscription and separately fenced operations. Orchard-routed shell settings alone select runtime customer connections. Provisioning is an authenticated private CLI, never a public setup/provision HTTP endpoint.

**Tech Stack:** Existing SDK 10.0.403 / .NET and EF 10.0.14 / SQL Server 2022 CU27-GDR1 / PowerShell 7.6.9; retain exact M0 pins and NuGet audit.

**Spec:** `docs/roadmap/saas-orchard-roadmap-v1.md` revision 1.3, §3.3, §5.1, §5.4–5.5, M1, §9.1; ADR 0002–0005. Baseline `4dec803d9c51c982a7c81d64cb682fb96c3e9b4d` includes merged M0 and both P3 fixes. The user's M1 instruction follows M0 owner review/merge; identity remains Conditional pending M2.

## Global constraints
- No platform/theme dependency on Orders/OrderApprovals; no identity, ACL, plan-changing or purge implementation beyond M1 contracts.
- No runtime EF migration/EnsureCreated; schema setup only in authenticated maintenance commands. No public bootstrap.
- Tenancy exclusively owns platform registry/operation/audit and customer identity streams; Orchard owns its own tables/migrations.
- Never seed missing/wrong identity in an existing customer database; never overwrite lifecycle while completing an operation.
- No executable tenant content, CMS administrator, arbitrary feature/recipe or upload API. No secrets in Git, logs or arguments.
- Acceptance requires actual SQL Server and full executed/non-skipped tests. Missing prerequisites remain BLOCKED, not PASS.

## Review focus
1. Existing database with absent/mismatched identity: retry fails closed instead of adopting it.
2. Simultaneous operation/retry and stale checkpoint: one resource owner; lifecycle CAS never overwrites suspension.
3. Setup/template/feature/upload routes under root and tenant prefixes: anonymous cannot initialize or mutate.
4. Schema/seed/feature/permission failure: no successful checkpoint/audit or business readiness.
5. Routed database and prefixed link/cache key: request body/header/token cannot select another database.

## Tasks and ownership

### Task 1 — Closed host boundary and domain contracts
Files: `src/Platform/SaaS.Abstractions/Tenancy/*.cs`, `src/Platform/SaaS.Tenancy/Domain/*.cs`, `src/SaaS.Web/Program.cs`, `tests/Unit/SaaS.UnitTests/*Tenan*Tests.cs`, `M1BoundaryTests.cs`.
Interfaces: `TenantId`, `TenantSlug`, subscription and operation states, `TenantContext`, `TenantReadiness`, prefixed links/cache keys. Unknown state fails closed. Slugs use lowercase ASCII letters/digits/hyphens with reserved system prefixes.
- [ ] Write and run behavioral red tests for hidden management HTTP surfaces; domain validation and lifecycle/operation completion.
- [ ] Implement contracts, request boundary and unit tests; adapt the M0 host tests to intentional M1 outcomes.
- [ ] Run complete unit/architecture suite, record commands and counts.

### Task 2 — Owned SQL models and durable operation protocol
Files: `src/Platform/SaaS.Tenancy/Data/*`, `Migrations/{Platform,Tenant}/*`, `Operations/*`, SQL integration tests.
Provides: fixed-connection `PlatformDbContext`; shell-bound `TenantDbContext`; platform registry, operation checkpoints and operational audit. Customer singleton identity is immutable. Common coordinator uses a SQL application lock held for the resource-mutating operation, separate short registry CAS transactions and persistent operation/fencing identifiers.
- [ ] Write negative SQL tests for duplicate slug, identity mismatch/missing, wrong target, runtime mutation and cross-DB denial.
- [ ] Generate/review separate SQL Server migrations/snapshots and implement registry/checkpoints/audit transactionally.
- [ ] Test concurrent retry, stale owner/version, checkpoint/audit failures and lifecycle preservation.

### Task 3 — Authenticated bootstrap/provision CLI and Orchard setup
Files: host maintenance command/adapters, `scripts/tenant-provision.ps1`, reviewed recipe, runbook.
Consumes: Task 1 contracts, Task 2 coordinator/models. Provides: bootstrap once; provision/resume by stable TenantId + operation ID; operator authorization from private environment/secret references; explicit target validation. Runtime, migrator and server provisioner connections remain distinct.
- [ ] Write red tests for missing/invalid operation credentials, duplicate/concurrent retries and partial setup.
- [ ] Implement only allowlisted recipe/features; setup/warm-up with bounded maintenance privileges, then reload with least-privilege runtime connections.
- [ ] Prove retry reconciliation and that unauthenticated HTTP cannot reach any maintenance path.

### Task 4 — Real routing/readiness, feature graph and SQL acceptance
Files: host shell adapter/readiness, architecture graph adapter/tests, `scripts/check.ps1`, new M1 SQL fixture/workflow and `docs/verification/m1.md`.
Consumes: all prior contracts. Readiness checks current registry/lifecycle/expiry/operation, database identity, exact EF + Orchard baseline, seed and feature/profile health, without repairing them. Cache/link helpers derive from routed context.
- [ ] Write red tests for alpha/beta/gamma/delta route isolation, unknown/reserved prefixes, body/header spoofing, schema/seed/feature faults and low-privilege restart.
- [ ] Implement fail-closed readiness and actual Orchard feature-dependency graph checks with violating fixtures.
- [ ] Regenerate genuine lock inventory, run full locked build/unit/architecture and real SQL gates, retain command exit codes/counts/SHA and report remaining gaps honestly.
- [ ] Self-review full branch; owner security/migration review and merge remain separate.
