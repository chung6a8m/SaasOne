# M1 tenancy and provisioning implementation plan

> Execution record: implementation verified at `0f9607b6db6c668d82e3e50a27ca1df159f607d8`; owner acceptance and merge remain separate. See `docs/verification/m1.md` for actual run/artifact identities and counters.

**Goal:** Implement roadmap M1: one closed-by-default Orchard host, fixed platform database, four independent customer shells, protected resumable provisioning and evidence-backed readiness.

**Specification:** `docs/roadmap/saas-orchard-roadmap-v1.md` revision 1.3, §3.3, §5.1, §5.4–5.5, M1 and §9.1; ADR 0002–0005. Start from `4dec803d9c51c982a7c81d64cb682fb96c3e9b4d`, including merged M0 and both P3 fixes. Identity remains Conditional pending M2.

**Architecture:** Preserve the modular monolith and selective Orchard 3.0.1 dependencies. Tenancy owns the fixed platform registry/operations/audit and customer identity streams. Native shell settings select runtime customer connections. Provisioning uses a private authenticated CLI, never a public HTTP setup endpoint. One trusted operations host holds both local process and SQL session locks through resource mutation and disposal; stale-owner SQL sessions must drain before retry. Cross-host automatic takeover is blocked.

**Pinned stack:** SDK 10.0.403, .NET/EF 10.0.14, PowerShell 7.6.9, SQL Server 2022 CU27-GDR1 build 16.0.4305.5. No M0 package/lock upgrades or NuGet-audit bypass.

## Invariants

- Platform/theme never depends directly or transitively on business modules. No early SSO, business ACL, Orders/OrderApprovals, plan transitions or purge implementation.
- Runtime never migrates EF schemas or repairs identity, seed or native baseline. Existing unidentified/mismatched customer DBs fail closed.
- Subscription/expiry remain separate from operation checkpoints. Common registry version, owner/fence and current SQL expiry guard completion.
- Checkpoint and operational audit writes share a transaction; failure never opens readiness.
- No public setup/admin, arbitrary feature/recipe, executable tenant content or upload surface. Secrets stay out of source, arguments and logs.
- Actual SQL execution, nonempty/non-skipped test evidence and cleanup are required before PASS.

## Execution ledger

The local environment lacked executable .NET/SQL prerequisites and direct GitHub access. An isolated connector-backed branch and pinned GitHub Actions runners supplied executed evidence. Temporary toolchain transport and migration-generation write workflows were removed from the final tree; runtime verification workflow permissions are read-only.

Tests preceded their major implementations. Final acceptance includes 74 non-SQL unit tests, 19 architecture tests and 38 real SQL/Orchard cases, all executed and passing with zero skipped. The inherited SQL smoke also passes. The source review corrected live shell registration, seeded-retry native-history repair and missing retained snapshots; each is covered by final regression checks.

Original interface ownership is retained: Abstractions owns contracts; Tenancy owns SQL/domain/coordination; Web owns the native Orchard adapter and HTTP/CLI composition; Build tooling owns graph/evidence inspection. No separate reviewer agent was available; owner review has not been represented as completed.
