## Locked choices

The product host composes the compiled `SaaS.Orders` module. Platform, shared contracts and themes cannot reference it. Orders never references the future Approvals implementation. The verified Orchard shell selects the customer connection; actor/client/entitlement are authenticated server state.

Orders owns schema/history `orders`; Auditing owns its nullable business-detail migration. Tenancy/Access/native table ownership is unchanged. The existing `TenantTransactionCoordinator` owns one connection/transaction for order, revision history, optional approval hook, audit and receipt. Contexts do not commit or retry independently. Transaction lock order is write gate, ACL snapshot, receipt partition, resource. Current authority is reread after serialization and a slow extension.

The proposed minimum fields are Number, CustomerName, Amount, Currency and plain-text Notes. Number is tenant-local unique uppercase ASCII, maximum 64; customer name maximum 160 UTF-16 units; notes maximum 2000; amount nonnegative decimal(18,2); currency three uppercase ASCII letters, not an ISO catalog assertion. Text is NFC-normalized, trimmed, with normalized line endings. Line items/tax/payment/cancel/delete/uploads are excluded. These are proposed product defaults, not previously confirmed requirements.

Create is Draft/revision 1/marker false. Each accepted edit/transition increments revision once with SQL rowversion and immutable snapshot. Creator is immutable. Edit permits Draft/Rejected and produces Draft while retaining the marker. Standard Submit confirms only without a marker. Current Approval entitlement or a marker requires current entitlement and a ready handler; absence fails closed. PendingApproval/Confirmed cannot be edited. Decisions bind revision/token, prohibit creator decisions and require a Reject reason. M4 registers no production handler or public decision route.

Create requires Create and ViewOwn. Edit/Submit require the persisted creator-selected Own/Others action plus corresponding read permission. Decisions require Decide, selected read access and non-creator. Deny cannot fall back to the alternate Own/Others permission. Replay uses the same current action/read/creator rules but not new-execution state/revision preconditions.

Partition = tenant + authenticated actor + client + action + case-sensitive 8–128-character ASCII key. SHA-256 request fingerprint includes normalized original resource/payload/expected revision/token. Receipt/result snapshot commits atomically; duplicate waiters reauthorize before replay or fingerprint conflict. Replay emits no new history/audit/hook effects. Seven days from transaction-recorded completion is the proposed replay window; expired receipts remain tombstones, not reusable keys. No automatic deletion/compaction exists.

The reader verifies database identity, migration/physical schema, state/history and sticky marker without relying on entitlement/handler. `ApprovalRequired && Status != Confirmed` is outstanding, including rejected/rework. Unknown state/schema fails closed. Product inventory remains closed to unfamiliar tables. Private `access-install` advances profile to v2; a verified M3 baseline may upgrade, an installed corrupt/future profile cannot be silently repaired/downgraded. HTTP cannot migrate.

UI/API share the service. Strict camelCase JSON and forms reject server-owned/unknown/duplicate fields, require command keys, and carry expected concurrency for existing orders. Encoded script-free web forms use antiforgery. Bodies are bounded at 32 KiB to support valid percent-encoded Unicode. Authorized list pages contain at most 50 entries, index 0–1000, no hidden-resource total.

## Implementation refinements and evidence

The planned transaction-bound AccessService read became a separate trusted platform contract, `TransactionAccessReader.ReadAsync`, rather than a public ACL-disclosure endpoint. Native request authority was extracted into one host boundary shared by Access and Orders. No dependency direction or authentication guarantee was relaxed.

The baseline source archive's local tree matched main exactly. The editing environment has no dotnet/pwsh/SQL and cannot clone GitHub directly; connector source/commits and pinned Actions provided runtime evidence. No local runtime success or independent reviewer is claimed.
