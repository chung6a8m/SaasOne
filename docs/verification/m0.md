## Acceptance procedure and remaining governance gate

Run the eight roadmap §7.1 commands from a fresh checkout as described in README. The normal CI foundation job executes the first seven via check.ps1; the independent SQL job executes the eighth against an isolated SQL Server and also rejects an incorrect target. Both jobs must pass on the same source commit. Check artifacts/verification/m0.json, SQL JSON and TRX counters, not only green job labels. New commits require fresh checks; this record identifies the tested baseline explicitly rather than claiming future branch heads are already verified.

The project owner still reviews/adopts the additional implementation selections in [the decision register](../decisions/m0-register.md) and [compatibility matrix](../compatibility/m0-matrix.md), including OS/CI/toolchain/package composition, indirect prerelease exceptions, physical schema ownership names and proposed identity lifetimes. The owner controls merge. This report does not change Conditional/Proposed ADR statuses or declare M1 started.

No product schema migration or production operation is included. The current secret scan is a conservative tracked-content/config check, not proof that arbitrary future credential formats can never leak.
