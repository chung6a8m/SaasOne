## Scope and owner decisions

The proposed operator UI is a private PowerShell console, not a privileged web dashboard. Initial installation has an empty ACL; the first application administrator requires explicit external approval. The tenant editor is a minimal full-document JSON form, not a polished product role designer. Resource operations retain the trusted single-operations-host constraint.

M3 has no Orders/Approvals business tables. The foundation reader fails closed on unfamiliar tables; contract fixtures cover persisted obligations and recovery child upgrades until M4/M5 provide product readers. Recovery here proves authorization/lifecycle reconciliation, not an M6 backup/restore, DNS/TLS/proxy, release or RTO/RPO rehearsal. Deployment secret-reference removal/recreation after purge is an explicit external runbook step; the CLI cannot modify a parent environment or external secret manager.

The verified scope is the pinned disposable environment and the tested prior-profile upgrade, not certification of arbitrary existing production baselines. Review the [operations runbook](../runbooks/m3-operations.md) and ADR 0002–0006 before deployment or merge. No new business modules, cross-host takeover, public operator endpoints or automatic ADR acceptance were introduced.
