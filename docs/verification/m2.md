## Acceptance coverage

### Central login, SSO and cryptographic authentication

A native Orchard account logs in once, then authorizes Alpha and Beta with independently named, prefixed Secure/HttpOnly cookies. Gamma lacks membership and receives no tenant grant. Two tabs retain their routed tenant context. Exact issuer+subject maps to immutable GlobalUserId; shared email never links distinct identities. Discovery advertises code/PKCE and not the resource-owner password grant. Token redemption and OIDC callbacks run the native protocol handlers with real signature, nonce/state, code and PKCE checks.

The protected bearer probe accepts a native signed `at+jwt` with RS256 and the proper issuer, audience, tenant and scope. Wrong signature/issuer/audience/subject/tenant, expired credentials and insufficient scope are rejected. Alpha's credential cannot call Beta even when the user belongs to both tenants; a refresh cannot switch tenant/client. UI mutations reject missing or another tenant's antiforgery value. Callback/logout/return URLs and unsolicited or wrong-prefix callbacks are negative-tested.

### Fresh authority, revocation and durable state

The original native-store proof establishes that customer stores do not own the issuer's token, including same-ID negative controls. Exact token/authorization/application/subject linkage, missing/expired records, native committed revocation, independent grants, fresh scopes, cache-enabled configuration rejection, cancellation and issuer-store outage are exercised.

The actual HTTP paths then prove that native authorization/access revocation reaches API and web validation. A dedicated web-first test prevents an earlier API call from being the hidden invalidation mechanism, preserves the independent Beta session, and repeats after a host/certificate reload. Ordinary access expiry does not falsely expire the separately bounded web session. Membership remove/re-add, subscription suspend/reopen and natural expiry/extension never restore old credentials. Native password lockout occurs at the configured attempt threshold; unlocking does not restore previously captured security stamps/grants. Required issuer/platform/account/membership read failures return 503 without cached Allow. Restarts retain persistent revocations and key validation.

### Refresh, concurrency and logout

Refresh rotation consumes a hash-bound token exactly once under a family-scoped SQL lock and records the resulting chain. Reuse revokes that family and related tenant session, not independent grants. Concurrent refresh cannot leave two valid chains; a lost response followed by replay requires a fresh login/authorization flow. Native token-endpoint errors remain OAuth errors. Tenant logout preserves other tenant access; global logout invalidates the account's sessions/grants across tenants.

### Production host and private operations

Acceptance tests call the same `IdentityRuntimeHost.Configure/Use` methods that Program uses. After initialization, the fixture removes all provisioner/operator/platform-migrator/customer-migrator connection variables and restarts the host with only restricted runtime credentials. Readiness, central login, Alpha/Beta SSO, protected API, refresh, missing-membership denial and cross-tenant rejection still work. Public admin/setup/feature/template/role mutation surfaces stay 404.

Corrupt native migration history closes production readiness and login with 503 while liveness remains available; the HTTP request does not repair the record. Retrying an already completed private initialization verifies only and succeeds even when any attempt to resolve a client secret would throw. The private CLI changes membership/account state and generations without reviving old credentials, preserves unaffected tenant grants and rejects invalid arguments.

A dedicated drift test adds an unexpected URI to the native application registration while leaving the independent platform registry unchanged. Production rejects it with 400 and no Location header before native code/error redirect handling. The registry is therefore an additional authoritative callback boundary, not merely a copy of a native allowlist.
